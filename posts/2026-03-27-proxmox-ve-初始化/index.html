Proxmox VE 配置域名+证书

  • 关于域名+证书访问 PVE WEB 介面有两种方式
    1. Datacenter (数据中心) - ACME - 账户 - 添加选择 Let’s Encrypt V2
      Datacenter (数据中心) - ACME - 质询插件 - 添加对应域名托管商 - 填入 Token
      PVE节点（宿主机）- 凭证 - ACME 添加 - 输入上面信息域名等 - 点击申请证书即可
    2. 通过创建CT 部署 Proxy Nginx Manager 反代配置域名证书

Proxmox VE 防火墙配置

  • Datacenter (数据中心) - PVE节点（宿主机） - 虚拟机 (VM)
    1. Datacenter - 防火墙 - 别名 - 添加指定IP规则
    2. Datacenter - 防火墙 - 安全群组 - 创建群组 - 添加上面创建的规则
    3. PVE节点 - 防火墙 - 添加安全群组（上面创建的群组名）- 启用
    4. 最后回到 Datacenter - 防火墙 -启用
    5. 虚拟机防火墙按需求创建，或交由用户自己处理

Proxmox VE API Token 配置

  • 宿主机命令行操作
# 创建 PVE 内部用户
# 第一步：创建用户本体
pveum user add terraform@pve

# 第二步：设置密码 (执行后会提示你输入两次)
pveum passwd terraform@pve

# 创建一个“最小权限”角色，这些权限涵盖了：创建、配置硬件、电源管理、克隆、以及使用存储空间的权利
pveum role add TerraformAdmin -privs "VM.Allocate VM.Audit VM.Config.CPU VM.Config.Memory VM.Config.Network VM.Config.Disk VM.Config.HWType VM.Config.Options VM.Config.CDROM VM.Config.Cloudinit VM.PowerMgmt VM.Console VM.Clone Datastore.AllocateSpace Datastore.Audit Sys.Audit"

# 生成 API Token，我们为 terraform 生成一个名为 terraform-token 的新令牌
# 生成 Token 并记下返回的 Value (Secret)
pveum user token add terraform@pve terraform-token --privsep 0

# 精确授权，不把权限给“人”，只给这个特定的“令牌”
# 1. 确保用户本体在 UI 上没权限 (如果之前没删的话)
pveum acl delete / -user terraform@pve -role Administrator

# 2. 将自定义角色绑定给新的 Token
pveum acl modify / -token 'terraform@pve!terraform-token' -role TerraformAdmin
  • PVE节点WEB介面操作
    1. 创建角色，直接用 Administrator 则略过
      • 数据中心 - 权限 - 角色 - 创建（选择想要的权限）
    2. 创建用户
      • 数据中心 - 权限 - 用户 - 添加 - 领域选择 pve (Proxmox VE authentication server)
    3. 创建 API Token
      • 数据中心 - 权限 - API Token - 添加 - 用户选择，令牌ID输入一个，并取消勾选特权分离
    4. 赋予权限
      • 数据中心 - 权限 - 添加 - 选择用户权限 - 路径 / ，用户 ， 角色

Proxmox VE 模版镜像制作

  • PVE节点VM模版创建
#  在 PVE 宿主机制作 Debian 12 模板
# 1. 下载镜像到 /root
cd /root
wget https://cloud.debian.org/images/cloud/bookworm/latest/debian-12-generic-amd64.qcow2

virt-customize -a debian-12-generic-amd64.qcow2 --install qemu-guest-agent --truncate /etc/machine-id

# 2. 创建一个 ID 为 1200 的 VM（此时它还没硬盘）
qm create 1200 --name "debian12-template" --memory 2048 --net0 virtio,bridge=vmbr1

# 3. 将镜像导入到 local-lvm（这里对应你图片里的存储名）
qm importdisk 1200 debian-12-generic-amd64.qcow2 local-lvm

# 4. 把导入的磁盘挂载给 VM
# 注意：导入后的磁盘名通常是 vm-1200-disk-0，可以在 local-lvm 视图查看确认
qm set 1200 --scsihw virtio-scsi-pci --scsi0 local-lvm:vm-1200-disk-0

# 5. 添加 Cloud-Init 驱动器到 local-lvm (或 local，建议 local-lvm)
qm set 1200 --ide2 local-lvm:cloudinit

# 6. 设置启动项、显示控制台、开启 Agent
qm set 1200 --boot c --bootdisk scsi0
qm set 1200 --serial0 socket --vga serial0
qm set 1200 --agent enabled=1

# 7. 转换成模板
qm template 1200
  • PVE节点CT模版创建
    1. local - CT Templates (CT 模板) - Templates (模板) - 搜索debian-12 / ubuntu-24.04 - 点击 Download
# 查看模板路径
pveam list local

Proxmox VE 宿主机图表修复方案

  • 如果当前pve节点图表日期显示为：1970-01-01 则需要执行下面命令修复
# 停止所有相关统计服务
systemctl stop pvestatd.service rrdcached.service rrdcached.socket

# 彻底清除所有 RRD 缓存数据
rm -rf /var/lib/rrdcached/db/*
rm -rf /var/lib/rrdcached/journal/*

# 重新启动并对齐系统时间
systemctl start rrdcached.socket
systemctl start rrdcached.service
systemctl start pvestatd.service
# 强制系统时间立即生效
hwclock --systohc

Proxmox VE 监控方案

  • 准备工作
# 创建用户
    - 数据中心 -> 权限 -> 用户 -> 添加 (用户名：monitoring@pve)
# 创建令牌
    - 数据中心 -> 权限 -> 令牌 -> 添加 monitoring@pve , 不要勾选 "特权分隔"
# 授权
    - 数据中心 -> 权限 -> 添加 -> 用户权限 -> 路径：/ , 用户：monitoring@pve , 角色：PVEAuditor (只读权限)
  • prometheus-node-exporter 宿主机安装
apt install prometheus-node-exporter
  • prometheus-pve-exporter 监控(外部部署)
# 安装
apt install python3.12-venv
python3 -m venv /opt/prometheus-pve-exporter
/opt/prometheus-pve-exporter/bin/pip install prometheus-pve-exporter

# 配置
mkdir -p /etc/prometheus
cat <<EOF > /etc/prometheus/pve.yml
default:
  # 注意：这里的 user 只需要填用户名@领域，不要带感叹号后面的部分
  user: "monitoring@pve"
  # 这里填感叹号后面的 Token ID 名称
  token_name: "monitoring-token"
  # 这里填那一串长的密钥
  token_value: "5da8f029-eb48-40e9-ad81-8bf4cebc892c"
  # 跳过证书校验
  verify_ssl: false
EOF

# 设置开机启动
useradd --shell /bin/false prometheus
chown -R prometheus:prometheus /opt/prometheus-pve-exporter
chown -R prometheus:prometheus /etc/prometheus/pve.yml

cat <<EOF> /etc/systemd/system/prometheus-pve-exporter.service
[Unit]
Description=Prometheus exporter for Proxmox VE
Documentation=https://github.com/znerol/prometheus-pve-exporter

[Service]
Restart=always
User=prometheus
ExecStart=/opt/prometheus-pve-exporter/bin/pve_exporter --config.file /etc/prometheus/pve.yml

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl start prometheus-pve-exporter
  • prometheus 配置
scrape_configs:
  - job_name: 'pve-virtual-vms'
    metrics_path: /pve
    scrape_interval: 30s  # 每 30 秒抓一次（给 PVE 留出喘息时间）
    scrape_timeout: 25s   # 允许最长 25 秒的等待时间
    params:
      module: [default]  # 对应 pve.yml 里的 [default]
      cluster: ['1']     # 抓取集群指标
      node: ['1']        # 抓取节点和虚拟机指标
    static_configs:
      - targets:
        - '[6666:6666:6666:128::2]' # 你的 PVE 宿主机 IPv6
    relabel_configs:
      # 将 targets 里的 IP 传给参数 target
      - source_labels: [__address__]
        target_label: __param_target
      # 将 instance 标签保留为 PVE 的 IP，方便在 Grafana 区分
      - source_labels: [__param_target]
        target_label: instance
      # 实际请求发送到 VPS 本地的 Exporter 端口
      - target_label: __address__
        replacement: 127.0.0.1:9221

Proxmox VE 虚拟机流量限制

  • 自动限额断网脚本
# PVE 宿主机创建一个目录存放统计数据：mkdir -p /opt/traffic_quota
# 创建脚本： nano /opt/traffic_quota/quota_check.py

import subprocess
import os

# --- 配置区 ---
VM_ID = "100"
IFACE = f"tap{VM_ID}i0"
LIMIT_GB = 500
DATA_FILE = f"/opt/traffic_quota/vm_{VM_ID}.stats"

def get_current_bytes():
    """获取网卡当前的累计字节数"""
    try:
        with open(f"/sys/class/net/{IFACE}/statistics/rx_bytes", "r") as f:
            rx = int(f.read().strip())
        with open(f"/sys/class/net/{IFACE}/statistics/tx_bytes", "r") as f:
            tx = int(f.read().strip())
        return rx + tx
    except FileNotFoundError:
        return 0

def get_last_total():
    """从文件读取上一次记录的累计量（应对网卡重启重置计数）"""
    if os.path.exists(DATA_FILE):
        with open(DATA_FILE, "r") as f:
            return int(f.read().strip())
    return 0

def save_total(amount):
    with open(DATA_FILE, "w") as f:
        f.write(str(amount))

def disable_network():
    """切断 VM 网络链接"""
    print(f"Quota Exceeded! Disabling network for VM {VM_ID}...")
    subprocess.run(["qm", "set", VM_ID, "--net0", "virtio,bridge=vmbr1,link_down=1"])

# 主逻辑
current_bytes = get_current_bytes()
# 注意：如果虚拟机重启，tap设备的计数会清零，这里需要配合持久化存储逻辑
# 这里简单演示：直接判断当前在线期间的流量
total_gb = current_bytes / (1024**3)

print(f"VM {VM_ID} Current Traffic: {total_gb:.2f} GB / {LIMIT_GB} GB")

if total_gb >= LIMIT_GB:
    disable_network()
