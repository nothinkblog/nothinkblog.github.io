Cert-Manager 签发域名证书

创建 Cloudflare API Token

省略。。。

安装 Cert-Manager

  • Cert-Manager 是一个独立的组件，专门负责证书的申请、续期和注入
# 添加 Jetstack Helm 仓库
helm repo add jetstack https://charts.jetstack.io
helm repo update

# 安装 Cert-Manager (包含所有的 CRD 资源)
helm install cert-manager jetstack/cert-manager \
  --namespace cert-manager \
  --create-namespace \
  --set installCRDs=true

# 验证
kubectl get pods -n cert-manager

配置 Cloudflare API 令牌

  • 要给 Cert-Manager 权限，让它能代表你去 Cloudflare 修改 DNS 记录
# 创建包含 Cloudflare Token 的 Secret
kubectl create secret generic cloudflare-api-token-secret \
  --from-literal=api-token=你的_CLOUDFLARE_API_TOKEN \
  -n cert-manager

创建 ClusterIssuer（证书颁发者）

  • 创建文件 cluster-issuer.yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-cloudflare
spec:
  acme:
    email: xxx@example.com
    server: https://acme-v02.api.letsencrypt.org/directory
    privateKeySecretRef:
      name: letsencrypt-cloudflare-account-key
    solvers:
    - dns01:
        cloudflare:
          apiTokenSecretRef:
            name: cloudflare-api-token-secret
            key: api-token
  • 执行应用
kubectl apply -f cluster-issuer.yaml

Traefik Ingress Controller

安装 Traefik

  • 添加源 traefik
helm repo add traefik https://traefik.github.io/charts
helm repo update
  • 创建 traefik-values.yaml
# traefik-values.yaml (兼容性最强版)

service:
  enabled: true
  type: LoadBalancer
  ipFamilyPolicy: PreferDualStack
  ipFamilies:
    - IPv4
    - IPv6
  annotations:
    # 填入你的 MetalLB IPv6 池名
    metallb.universe.tf/address-pool: dual-stack-pool

# 使用额外参数直接定义行为，避开 Helm Schema 限制
additionalArguments:
  - "--accesslog=true"            # 开启访问日志
  - "--metrics.prometheus=true"   # 开启 Prometheus 监控指标
  - "--providers.kubernetesingress.allowEmptyServices=true"
  - "--entrypoints.web.http.redirections.entryPoint.to=websecure"
  - "--entrypoints.web.http.redirections.entryPoint.scheme=https"
  - "--entrypoints.websecure.http.tls=true"
  # 这里不需要再写 acme 存储，因为证书由 Cert-Manager 提供

ports:
  web:
    port: 8000
    exposedPort: 80
    protocol: TCP
  websecure:
    port: 8443
    exposedPort: 443
    protocol: TCP

# 开启 Dashboard 方便排查
ingressRoute:
  dashboard:
    enabled: true
  • 执行安装
helm install traefik traefik/traefik -n traefik -f traefik-values.yaml
  • 查看 MetalLB 分配的 IP
kubectl get svc -n traefik

Cloudflare 做 DNS 解析

  • 添加一条记录，填入刚才 kubectl get svc -n traefik 查到的那个 EXTERNAL-IP 中的 IPv6 地址

部署web应用并申请证书

  • 创建 my-app.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-app
  namespace: traefik # 建议先放在同一个空间测试
spec:
  replicas: 1
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:alpine
---
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
  namespace: traefik
spec:
  ports:
  - port: 80
    targetPort: 80
  selector:
    app: nginx
  • 执行部署
kubectl apply -f my-app.yaml
  • 创建 my-ingress.yaml (Ingress 触发自动证书申请)
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: nginx-ingress
  namespace: traefik
  annotations:
    # 告诉 cert-manager 使用我们之前创建的那个 ClusterIssuer
    cert-manager.io/cluster-issuer: "letsencrypt-cloudflare"
    # 强制使用 traefik 作为入口控制器
    kubernetes.io/ingress.class: traefik
spec:
  tls:
  - hosts:
    - test.admin.com  # 替换成你刚才在 Cloudflare 解析的域名
    secretName: nginx-web-tls # cert-manager 会自动创建并填充这个 Secret
  rules:
  - host: test.admin.com # 替换成你的域名
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: nginx-service
            port:
              number: 80
  • 执行应用
kubectl apply -f my-ingress.yaml
  • 验证
# 检查证书请求状态
kubectl get clusterissuer letsencrypt-cloudflare

kubectl get certificate -n traefik

kubectl get challenge -n traefik

# 如果卡住了，看具体报错
kubectl describe certificate nginx-web-tls -n traefik

# 看 Cert-Manager 的日志
kubectl logs -n cert-manager -l app=cert-manager -f

查看已申请的域名证书

  • 查看概要列表
# 查看所有命名空间下的证书及其到期时间、是否就绪
kubectl get certificate -A
  • 查看详细信息（看它包含了哪些域名）
# 替换为你的证书名
kubectl describe certificate nginx-web-tls -n traefik
  • 查看颁发者状态
# 确认你的 Cloudflare 渠道是否依然畅通
kubectl get clusterissuer
  • 一键查看所有证书及其域名
# 显示：命名空间、证书名、具体的域名、是否就绪以及过期时间
kubectl get certificate -A -o custom-columns="NAMESPACE:.metadata.namespace,NAME:.metadata.name,DOMAIN:.spec.dnsNames[*],READY:.status.conditions[?(@.type=='Ready')].status,EXPIRES:.status.notAfter"

Traefik 仪表盘

  • 生成 Basic Auth 密文
  • 在 Kubernetes 的 Secret 中，data 字段要求所有内容必须是 Base64 编码，流程是：
    明文密码 -> htpasswd加密串 -> Base64编码 -> 写入 Secret
# 这里假设用户名 admin，密码 admin123
# 如果没有 htpasswd 命令，可以用在线生成器：
# 语法：htpasswd -nb [用户名] [密码]
htpasswd -nb admin admin123

# 下面这个 base64 对应 admin:admin123
echo "admin:\$apr1\$m5v8p6d0\$K/U1R5M8Wv9R2vG.X/yU/." | base64
  • 应用安全配置，编写 new-dash-secure.yaml
  • 创建 Ingress 触发证书和路由
# 1. 账号密码 Secret (保持不变)
apiVersion: v1
kind: Secret
metadata:
  name: dash-auth-secret
  namespace: traefik
data:
  users: GFwcjEkbTV2OHAy9VMVI1TThXdl9SMnZHLlgveVUvLgo=
---
# 2. Basic Auth 中间件
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: dash-basic-auth
  namespace: traefik
spec:
  basicAuth:
    secret: dash-auth-secret
---
# 3. 使用 IngressRoute 暴露仪表盘
apiVersion: traefik.io/v1alpha1
kind: IngressRoute
metadata:
  name: traefik-dashboard-secure
  namespace: traefik
spec:
  entryPoints:
    - websecure
  routes:
  - match: Host(`dash.new-domain.com`) # 换成你的新域名
    kind: Rule
    services:
    - name: api@internal # 在这里使用 api@internal 是完全合法的
      kind: TraefikService
    middlewares:
    - name: dash-basic-auth
  tls:
    # 关键：这里直接引用由 Cert-Manager 生成的证书 Secret
    secretName: dash-new-tls-secret 
---
# 4. 重点：保留一个最简 Ingress 只为了触发 Cert-Manager 申请证书
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: dash-cert-trigger
  namespace: traefik
  annotations:
    cert-manager.io/cluster-issuer: "letsencrypt-cloudflare"
spec:
  ingressClassName: traefik
  tls:
  - hosts:
    - dash.new-domain.com
    secretName: dash-new-tls-secret # 触发证书申请
  rules:
  - host: dash.new-domain.com
    http:
      paths:
      - path: /placeholder
        pathType: Prefix
        backend:
          service:
            name: placeholder-service # 随便写一个，我们只用这个 Ingress 拿证书
            port:
              number: 80
  • 应用配置
kubectl apply -f new-dash-secure.yaml
  • 检查证书状态
kubectl get cert -n traefik -w

部署通配符证书

  • 创建通配符证书资源，编写 wildcard-cert.yaml
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: wildcard-new-domain
  namespace: traefik
spec:
  # 证书签发后，会自动存入这个 Secret 中
  secretName: wildcard-new-domain-tls-secret 
  issuerRef:
    name: letsencrypt-cloudflare
    kind: ClusterIssuer
  dnsNames:
    - "*.new-domain.com"  # 匹配所有二级域名
    - "new-domain.com"    # 匹配根域名


# 执行部署
kubectl apply -f wildcard-cert.yaml

# 查看证书状态
kubectl get cert -n traefik -w

# 查看详细挑战过程
kubectl get challenge -n traefik

Traefik 速率限制中间件

  • 配置 Traefik 速率限制中间件 (RateLimit)，编写 middleware-ratelimit.yaml
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: global-ratelimit
  namespace: traefik
spec:
  rateLimit:
    average: 10   # 平均每秒允许 10 个请求
    burst: 20      # 允许瞬间突发 20 个请求


# 执行部署
kubectl apply -f middleware-ratelimit.yaml

# 查看速率限制中间件
# 查看中间件列表
kubectl get middleware -n traefik

# 查看存放证书的“箱子”
kubectl get secret -n traefik wildcard-new-domain-tls-secret

删除资源

  • 清理步骤如下：
# 删除 Ingress 路由
kubectl delete ingress nginx-ingress -n traefik

# 删除 Deployment 和 Service
kubectl delete deployment nginx-app -n traefik
kubectl delete service nginx-service -n traefik

# 删除 Certificate 对象
kubectl delete certificate nginx-web-tls -n traefik

# 删除生成的证书 Secret (存放证书文件的地方)
kubectl delete secret nginx-web-tls -n traefik
  • 运行以下命令确认资源已经消失
# Ingress
kubectl get ingress -n traefik

# 证书
kubectl get cert -n traefik

# 密钥
kubectl get secret -n traefik

# 挑战请求	
kubectl get challenge -n traefik
